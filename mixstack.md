# 仓颉异常包含ArkTS调用栈设计方案

## 一、设计背景

在OpenHarmony系统中，仓颉语言与ArkTS语言进行跨语言调用时，当仓颉代码抛出异常，当前异常处理机制只能显示仓颉侧调用栈，无法展示完整的跨语言调用链，导致开发者难以定位问题。

本方案旨在实现仓颉异常中包含完整的ArkTS调用栈信息，在faultlog中统一展示混合语言调用栈。


## 五、关键技术实现

### 5.1 栈顺序保证机制

#### 5.1.1 跨语言调用场景分析

```
真实调用链示例:

ArkTS应用代码
    ↓ 调用
FFI桥接函数 (CangjieFFI_Call)
    ↓ 调用
仓颉入口函数 (cangjie_entry)
    ↓ 调用
仓颉业务函数1
    ↓ 调用
仓颉业务函数2
    ↓ 调用
异常抛出点 ◄── 当前执行位置
```

```

                              │

┌─────────────────────────────────────────────────────────────────────┐
│  Step 1: 从异常点开始回溯仓颉栈                               │
│  ┌───────────────────────────────────────────────────────────┐    │
│  │ 回溯方向: 栈顶 → 栈底 (低地址 → 高地址)                 │    │
│  │                                                          │    │

│  │                                                          │    │

│  │ ├── 遇到FFI桥接函数帧                                   │    │

└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼

│  │                                                          │    │

│  │ [FFI桥接函数] → [仓颉入口函数] → [FFI桥接函数] →         │    │
│  │ [ArkTS应用代码]                                           │    │
│  │                                                          │    │
```

```
├─────────────────────────────────────────────────────────────────────┤
│  方法3: 地址范围检测                                          │

```
