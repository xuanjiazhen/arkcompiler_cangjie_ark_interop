# 红蓝对抗审视 — 第 6 轮：§14 概述 & §15 foreign 声明

**审视范围**：§14.1–§14.3, §15.1–§15.4
**日期**：2026-04-11

---

## 一、红军攻击意见（用户/架构师角色）

### 攻击 6-1：§14 "单进程仅支持一个 ArkTS 运行时实例"限制过强

§14.3 约束"单进程仅支持一个 ArkTS 运行时实例"。在复杂应用中，不同业务模块可能需要隔离的 ArkTS 上下文（如安全沙箱、多租户场景）。此限制应说明技术原因和未来扩展计划。

**严重程度**：中  
**影响范围**：§14.3

### 攻击 6-2：§14.3 运行时初始化的三种策略缺少错误处理

§14.3 列出三种策略（ArkTS 入口启动、仓颉入口启动显式初始化、惰性创建），但未讨论初始化失败的处理：
- 显式初始化失败时返回什么错误？
- 惰性创建失败时，foreign 调用是否抛异常？抛什么异常？
- 重复初始化是幂等还是报错？

**严重程度**：高  
**影响范围**：§14.3

### 攻击 6-3：§14.1 特性支持矩阵中 `namespace` 标记为"不支持"，但 §2.6 多包合并模块使用了 namespace

§14.1 说仓颉调用 ArkTS 时 `namespace` 不支持，但 §2.6（ArkTS 调用仓颉）中多包合并导出时生成 `namespace`。这造成不对称——仓颉导出时可用 namespace，但仓颉调用时无法访问 ArkTS 侧 namespace。

**严重程度**：中  
**影响范围**：§14.1, §2.6

### 攻击 6-4：§15.3 module 路径"编译器仅校验字面量语法"风险过高

§15.3 说编译器仅校验 `module` 字面量语法，模块可解析性由 ArkTS 侧构建/运行时负责验证。这意味着拼写错误的模块路径到运行时才能发现。应提供至少一层编译期检查（如相对路径文件是否存在）。

**严重程度**：高  
**影响范围**：§15.3

### 攻击 6-5：§15.2 "foreign func 不支持命名参数和参数默认值"的限制未充分说明理由

§15.2 说 foreign func 不支持命名参数和参数默认值，但未解释技术原因。ArkTS/TypeScript 函数可以有命名参数和默认值，为何在 foreign 声明中不能映射？

**严重程度**：低  
**影响范围**：§15.2

### 攻击 6-6：§15.4 name 选项仅对 foreign func 说明，对 foreign class 成员未说明

§15.4 的 `name` 选项示例仅展示了 foreign func 的重命名。当 foreign class 内的方法需要重命名时（如 ArkTS 侧方法名是仓颉保留字），是否也支持 `name` 选项？

**严重程度**：中  
**影响范围**：§15.4

## 二、裁判裁决（设计者角色）

| 编号 | 判定 | 理由 |
|------|------|------|
| 6-1 | **部分采纳** | 单实例是当前版本的技术约束。应补充简要技术原因（ArkTS 运行时全局状态依赖现有宿主环境架构）并标注"未来版本可能放开"。 |
| 6-2 | **采纳** | 初始化错误处理必须明确。应补充：显式初始化失败抛异常（含错误原因）、惰性创建失败抛 `REFERENCE_BEYOND_REACH` 异常、重复初始化为幂等操作（返回已有实例）。 |
| 6-3 | **部分采纳** | 不对称是设计限制，但应明确说明。在 §14.1 的 namespace 行说明中补充："ArkTS 侧的 namespace 成员可通过在 `module` 路径中指定模块后使用 `name` 选项访问具体导出名来间接访问。" |
| 6-4 | **部分采纳** | 完全编译期解析不可行（系统模块和 ohpm 包的可用性依赖构建环境）。但可提升：对相对路径模块（`./`、`../`）进行编译期文件存在性检查；对其他路径类别仅做语法校验。 |
| 6-5 | **采纳** | 应补充技术原因：foreign 声明是仓颉侧的签名声明，不包含实现体；命名参数在仓颉调用时按位置传参映射到 ArkTS 侧参数位置；参数默认值属于 ArkTS 侧实现行为，仓颉编译器无法获取。 |
| 6-6 | **采纳** | `name` 选项应同样适用于 foreign class 的成员方法。应在 §15.4 补充 foreign class 成员使用 `name` 的示例。 |

## 三、蓝军修改方案

### 修改 6-1：§14.3 增加单实例约束原因
将"当前版本约束：单进程仅支持一个 ArkTS 运行时实例。"修改为："当前版本约束：单进程仅支持一个 ArkTS 运行时实例，原因是 ArkTS 运行时的全局状态管理依赖现有宿主环境架构。未来版本可能支持多实例隔离。"

### 修改 6-2：§14.3 补充初始化错误处理
在初始化策略列表后增加：

> **初始化错误处理：**
> - 显式初始化失败时，抛出包含失败原因的 `REFERENCE_BEYOND_REACH` 异常
> - 惰性创建失败时，`foreign` 调用抛出 `REFERENCE_BEYOND_REACH` 异常
> - 重复初始化为幂等操作，返回已有运行时实例，不重新创建

### 修改 6-3：§14.1 namespace 行增加间接访问说明
将 namespace 行的说明列修改为："使用模块绑定替代。ArkTS `namespace` 的成员可通过模块路径 + `name` 选项间接访问。"

### 修改 6-4：§15.3 增加编译期检查层级说明
在"编译器仅校验 `module` 字面量语法"后修改为："编译器对 `module` 路径分级检查：对相对路径（`./`、`../`）进行文件存在性编译期校验；对系统模块、Kit 模块、HAR/HSP 包和 ohpm 三方包仅做路径格式语法校验，可解析性由构建环境和 ArkTS 侧验证。"

### 修改 6-5：§15.2 补充技术原因
在"foreign func 不支持命名参数和参数默认值"后增加："原因：`foreign` 声明是仓颉侧的签名声明，不包含实现体。参数默认值属于 ArkTS 侧的实现行为，仓颉编译器无法获取。仓颉侧按位置传参调用 ArkTS 函数，命名参数不影响调用语义。"

### 修改 6-6：§15.4 补充 foreign class 成员 name 示例
在 §15.4 增加：

```cangjie
@Interop[ArkTS, module: "utils"]
foreign class StringHelper {
    @Interop[ArkTS, name: "valueOf"]
    func value(): String  // ArkTS 侧实际方法名为 valueOf
}
```
