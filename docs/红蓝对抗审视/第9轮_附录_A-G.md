## 一、红军攻击意见（用户/架构师角色）

### 攻击 9-1：附录 A 错误码 34300001 INDEX_OUT_OF_RANGE 无触发场景引用

附录 A 列出 `INDEX_OUT_OF_RANGE`（34300001）但仅说明"数组索引越界"，主文中没有任何章节引用此错误码的触发点。相比之下，其他四个错误码（34300002–34300005）在 §12.2 中都有详细章节引用。（注：此问题在第 5 轮 5-6 已提出，但附录 A 侧也需修正。）

**严重程度**：高  
**影响范围**：附录 A

### 攻击 9-2：附录 A 错误码连续编号（34300001–34300005）预留空间不足

当前 5 个错误码占用 34300001–34300005。若未来需要新增错误码（如网络错误、序列化错误等互操作特定场景），连续编号可能很快耗尽所在段。是否应预留范围或分组编码？

**严重程度**：低  
**影响范围**：附录 A

### 攻击 9-3：附录 B JSInteropType 列表缺少 Rune、BigInt、元组、函数类型

附录 B "自动满足 JSInteropType 约束的类型列表"中未列出：
- `Rune`（§3.1 已映射为 number）
- `BigInt`（§4.1 已映射为 bigint）
- 元组类型 `(T1, T2, ...)` where Ti 满足 JSInteropType
- 函数类型 `(T1, ...) -> R` where 各类型满足 JSInteropType

这些类型在 §3 中有明确的映射规则，应在附录 B 中列出。

**严重程度**：高  
**影响范围**：附录 B

### 攻击 9-4：附录 C.1 伪代码使用的 postJSTask 接口与 §13.2 的 postJSTask 一致性未确认

附录 C.1 的伪代码使用 `postJSTask` 投递任务，§13.2 也提到 `postJSTask`。但附录 C.1 同时提到"当前接口层实现为 `ARKTS_CreateAsyncTask`"——两个名称不一致。是 `postJSTask` 是伪代码概念名，`ARKTS_CreateAsyncTask` 是实际 API 名？应澄清。

**严重程度**：低  
**影响范围**：附录 C.1

### 攻击 9-5：附录 C.2 可行性分析缺少性能评估

附录 C.2 分析了 Promise 映射的可行性，但仅从功能角度讨论（"能否做"），未从性能角度评估（"能做到多快"）。Promise 桥接涉及至少两次跨线程通信，性能开销是否可接受？

**严重程度**：中  
**影响范围**：附录 C.2

### 攻击 9-6：附录 D const 内联分析未讨论枚举常量

附录 D 分析了基础类型和非基础类型的 const 内联可行性，但未讨论 §9 中枚举类型的常量导出。`const` 声明的枚举值（如 `const COLOR: Color = Color.Red`）是否内联？

**严重程度**：低  
**影响范围**：附录 D

### 攻击 9-7：附录 E C 互操作对比表格不完整

附录 E 列出了 10 项对比，但缺少以下重要对比维度：
- 错误处理机制（C 互操作无异常桥接 vs ArkTS 互操作有双向异常映射）
- GC 交互（C 无 GC vs ArkTS 有 GC，需双 GC 联动）
- 闭包/回调支持（C 互操作通过 CFunc vs ArkTS 通过 JSFunc）

**严重程度**：中  
**影响范围**：附录 E

### 攻击 9-8：附录 F 版本记录缺少变更影响范围评估

附录 F 的版本记录仅有"变更摘要"，缺少"影响范围"和"不兼容变更"信息。2.3.0→2.4.0 的变更是否引入了与 2.3.0 不兼容的行为？

**严重程度**：中  
**影响范围**：附录 F

## 二、裁判裁决（设计者角色）

| 编号 | 判定 | 理由 |
|------|------|------|
| 9-1 | **采纳** | 与第 5 轮 5-6 一致，附录 A 的 INDEX_OUT_OF_RANGE 说明列也应增加引用场景。 |
| 9-2 | **驳回** | 错误码编号方案遵循 HarmonyOS 系统错误码分配规范（34300xxx 段），预留空间由系统统一管理。5 个错误码在可预见范围内足够。 |
| 9-3 | **采纳** | 附录 B 必须与 §3 章的类型映射保持一致。缺少的类型应补充列出。 |
| 9-4 | **采纳** | 应统一用语：伪代码中使用 `postJSTask` 作为概念名，括号注明当前实现接口名。 |
| 9-5 | **驳回** | 附录 C.2 是可行性分析，不是性能基准。性能评估属于工程实现阶段。§21.1 已说明跨线程开销为"微秒级"。 |
| 9-6 | **驳回** | `const` 声明的枚举值在 ArkTS 侧已通过 `const enum` 内联（§9），与 §10.1 的 `const` 变量内联是不同的导出路径。附录 D 仅分析全局 `const` 变量，不适用于枚举。 |
| 9-7 | **采纳** | 对比表格应覆盖更多维度以提供完整参考。 |
| 9-8 | **部分采纳** | 版本记录增加"不兼容变更"列。2.3.0→2.4.0 为条款修订，无不兼容变更，标注"无"即可。 |

## 三、蓝军修改方案

### 修改 9-1：附录 A INDEX_OUT_OF_RANGE 增加引用
在附录 A 34300001 行的说明列修改为："数组索引越界（`JSArrayEx` 下标访问越界等场景）"。

### 修改 9-3：附录 B 补充缺失类型
在附录 B 表格中增加以下行：

| 类别 | 类型 |
|-----|------|
| 字符类型 | `Rune` |
| 大整数类型 | `BigInt` |
| 元组类型 | `(T1, T2, ..., Tn)`（各元素类型满足 JSInteropType） |
| 函数类型 | `(T1, ..., Tn) -> R`（参数和返回类型满足 JSInteropType） |

### 修改 9-4：附录 C.1 统一术语
将 `postJSTask` 的首次出现处增加注释："`postJSTask`（概念名；当前接口层实现为 `ARKTS_CreateAsyncTask`）"。删除后文重复说明。

### 修改 9-7：附录 E 补充对比维度
在附录 E 表格增加以下行：

| 特性 | C 互操作 | ArkTS 互操作 |
|-----|---------|-------------|
| 异常/错误处理 | 无跨语言异常桥接，需手动检查返回值 | 双向异常/错误自动转换映射 |
| GC 交互 | C 侧无 GC，开发者手动管理内存 | 双 GC 联动（仓颉 GC + ArkTS GC），自动生命周期管理 |
| 回调/闭包 | `CFunc` 类型，需手动管理 | `JSFunc` 类型，自动线程切换 |

### 修改 9-8：附录 F 增加兼容性列
将附录 F 版本记录表增加"不兼容变更"列：

| 版本 | 日期 | 变更摘要 | 不兼容变更 |
|------|------|----------|-----------|
| 2.4.0 | 2026-04-11 | 根据检视意见调整... | 无 |
| 2.3.0 | 2026-03-19 | 草稿基线版本 | — |
